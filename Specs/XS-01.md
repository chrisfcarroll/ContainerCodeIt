Look at early versions of the code base. The original idea, before we added more functionality, was a single short user-maintained Dockerfile.

1. Let's recreate that minimalist, developer-maintainable spirit!

In a subdirectory in this folder, create an 'XS' (for extra secure and extra small) version of the project that is just:
- a user-maintained dockerfile
  - including claude and opencode v2 agents.
  - excluding any toolchain. Just bash.
- two snippets of Dockerfile lines
  - a snippet for adding uv/python as a toolchain
  - a snippet for adding codex as an agent
- powershell and bash scripts for code-it, which must be short and human-readable

the tests for this version should go under the main tests folder, in their own xs folder.

The code-it scripts should retain all and only the features developed since the early versions which can be done without exploding the size of the script, and without wanting recourse to a lib/ directory. For instance:
- Have no parameter for ports
- Have parameter passing 
	- -- for pass through to the agent
	- -D: or --D: for pass through to docker or the container runtime.
- The ability to work with both docker and apple containers
- Mounting the work-dir at a calculated path instead of always at /work.
- Locale.


Embed the firstrun script into the code-it file. All the first run experience will do, is offer to copy your existing claude and opencode config into code-it's config directory. That is all. It will have a single yes/no question for "Shall I copy your existing Claude and OpenCode config so that your containerised agents can use your current logins?"

2. Having done this, commit. Then review the code and see if you can make it simpler. If you can, commit.

3. Then, add a short section to the root README.md under Quick Start, with heading Quick Start XS Version

If you are both paranoid and comfortable with editing your own Dockerfile, you may prefer (link to README in the XS/ directory), which is a much smaller, human-verifable codebase that also containerises your agents but without the user-friendly functions.

And, create the README.md for the XS version which will also be much briefer.

It wil include the summary, a QuickStart, a link to the full fat version, first run, and options.
